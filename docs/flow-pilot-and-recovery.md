# Optional FLOW pilot and recovery

Choose one non-sensitive GitHub or Jira issue and a private local profile outside your source checkout. `ai-workbench work init --dry-run` previews the root; `work open --dry-run` previews each selected reference. Opening an item creates local metadata only. It does not fetch a tracker issue, clone code, or launch an agent. The retained `flow-history` branch records checkpointed `TASKS.md` definitions and outcomes; profile-side registry, operation journal, source cache, and publication outbox are private local files and are not backed up by Git automatically.

Run the synthetic suite before a pilot: `uv run pytest -q tests/test_flow_journey.py tests/test_flow_tasks.py tests/test_flow_history.py tests/test_flow_publication.py tests/test_flow_source.py tests/test_flow_relations.py`. A live provider check requires an explicitly selected disposable issue and authorization; fixture compatibility does not verify live GitHub/Jira access. Record the tested commit and provider/tool versions, sanitized results, and limits. FLOW is optional and existing actions continue without links.

For interruption, inspect `work task reconcile`, `work task history`, the local operation status, and the exact metadata Git commit. Reuse the original operation ID for uncertain publication; `publication_pending` means an API outage or ambiguous response, while `reconciliation_needed` requires reading both the server projection and local checkpoint before queueing a new version. A raw `[x]`, removed line, or source tracker closure is not proof of accepted completion. Missing uncommitted edits cannot be recovered from Git. Do not garbage collect away the retained metadata branch.

For backup, deliberately back up the private profile directory **and** the metadata Git repository together to an access-controlled destination. Restore both, verify file ownership and mode, and inspect operation state before continuing. To roll back integration, stop using publication and source-record tools; leave the metadata history and accepted Workbench actions intact. Do not delete the profile or rewrite `flow-history` as a rollback shortcut. This procedure does not deploy or enable any collector.

To adopt a selected legacy checklist, use the local `flow_migration_preview` MCP tool on one explicit absolute `.md` file. It lists proposed stable IDs, active rows, checked claims, and unsupported nested rows. Review the entire preview before `flow_migration_apply` with its short-lived token. The original file stays untouched; checked rows are skipped and require separate historical interpretation. The importer does not infer completion or execute embedded instructions. A changed source or target rejects adoption. If a Git hook or process interruption stops a multi-row import, inspect the local operation history and resulting task IDs, then take a fresh preview. Stable row operation IDs replay already committed rows without duplicating them; do not assume the partial import was rolled back.

Task summaries are withheld from the server by default. After choosing a profile and checking that its local task titles are suitable for the Workbench operator audience, run `uv run python -m starforge_workbench.flow_publication --profile /private/profile.json summary-disclosure enable`. Future explicitly queued publications may then include only task ID, a 120-character title, and blocked/review flags. Disabling the setting affects future queues; publish the current revision again with a new operation ID and server version to clear an already published summary. Existing outbox entries retain their captured bytes. The server still cannot observe edits made after the last publication.
