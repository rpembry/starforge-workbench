# GPU reservation adapter slice

This is a testable foundation stacked on the policy in #194. It is **not** an installed service or a production miner integration. `gpu_adapter.py` accepts a narrow `OwnedController` implementation; no real process controller is included. Only synthetic tests instantiate it.

## Local authority boundary

- `ReservationSocket` binds one owner-private Unix socket under an existing `0700` directory and gives it mode `0600`. Requests are one JSON line, at most 4096 bytes, with a three-second read deadline. The only verbs are acquire, renew, release and status. It accepts no shell command, arbitrary PID or TCP address.
- Linux `SO_PEERCRED` supplies peer PID/UID/GID. The server requires its own UID and delegates stable owner identification to an injected supervisor resolver. The resolver must bind the peer to a supervised workload scope whose *entire* process tree can be checked later. The code provides **no default resolver** and no general-purpose host controller. Same-UID callers share an OS trust boundary; socket mode alone is not process-level isolation or authorization against a malicious same-UID process. Lease tokens remain private bearer values.
- `Registry` requires an absolute regular SQLite file with owner UID and mode `0600` under an owner-private directory; symlinks and an existing file without valid state are rejected. The snapshot includes leases, request-key history and boot clock identity. State and one desired START/STOP intent are written in one `BEGIN IMMEDIATE` transaction with full synchronous durability. The caller serializes all operations with a lock. A failed persistence write disables that adapter instance.
- `LocalAdapter.tick` observes before choosing an effect, commits the current policy state and effect intent, then calls an idempotent, exact-owner `OwnedController.apply`. On restart it observes again rather than blindly replaying a possibly obsolete START. An unexpected miner presence under an active lease leads to STOP; a newly acquired lease supersedes an older START intent. This is a latest-state outbox, not an arbitrary action queue.
- An acquire response is initially pending. A later controller tick must observe both the *controller-owned* background process and its GPU context absent before status can be granted. An unknown observation never grants or starts work. When exact process identity cannot be established, the adapter must report unavailable and require operator recovery rather than signal an arbitrary process.

## Required production work

Before opt-in installation, provide and review a host-specific `OwnedController` and peer-to-workload-scope resolver. They must track immutable process generation and group identity, bound stop attempts and exit waits, determine when the miner-owned GPU context is gone without requiring global VRAM to be empty, and prove a higher-priority workload scope ended before releasing an expired hold. Those capabilities are deliberately absent from this slice.

Test the private adapter with fake clock/controller crashes and socket clients, then inspect actual scheduler and process ownership in a separate read-only migration review. Prepare private configuration, single-controller cutover and rollback steps. Do not start a second controller alongside the existing one. The installed scheduler and existing idle gate remain authoritative; optional time windows do not impose a nightly default.
