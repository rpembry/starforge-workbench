# Quick status companion

`/status/` is a small foreground view over canonical Workbench data. It uses existing operator authentication and requests `/api/status/{attention,jobs,hosts,allowances}` only for checked widgets. A separate authenticated `/api/status/config` read supplies the private reporting timezone and current identity in memory. The browser stores widget names per browser profile in local storage, not account, job or notification payloads. Checkbox changes cancel prior requests and ignore late responses. Network refresh is explicit except on foreground resume, which checks identity and reconciles a fresh snapshot. Hidden tabs clear private cards and abort requests. In-memory countdowns and freshness labels update every 30 seconds while visible; they never create a fresh observation. Offline state never presents cached data as live.

The allowance read model stores narrow manual observations in protected server SQLite. `POST /api/allowances/manual` accepts provider, product, local profile, bucket, window, timezone-aware `observed_at`, optional timezone-aware `reset_at`, and optional finite `remaining_percent`. No provider credentials or full exports are accepted. Observations are immutable for their exact key and time; an older import cannot replace a newer one. The latest per provider/product/profile/bucket/window is shown. Missing fields stay unknown and unusual reported percentages are preserved. The UI uses the configured reporting timezone and recomputes reset countdowns at render. Passing a reset marks refresh due, not a replenished balance. Entries older than one hour are stale; newer entries remain labeled manual, never verified live.

This slice has no automatic Codex, Claude or Gemini quota adapter. Supported interfaces must pass the evidence gate in [provider capabilities](provider-capabilities.md) before supplying data. No quota is inferred from message counts, context use or billing. The manual endpoint is accessible through authenticated generic `wb-api` requests; it is not a new MCP tool. Stale job records retain their reported state. No collector record means host visibility unknown.

The route uses existing operator authority. It does not issue a scoped companion credential, request notification permission, deliver push, subscribe to RGB, or cache private payloads offline. No hardware driver is required. Reset choices restores the four default widgets; browser site-data controls clear the selection. An HTTP 401/403 on config or widget reads clears all in-memory status and prompts sign-in. A profile change is checked on refresh/resume and replaces the previous view. This is a foreground check, not immediate notification of logout in another tab.

## Installable shell boundary

The manifest starts at `/status/` with the same scope and exact 192- and 512-pixel derivatives of the existing logo for [Chrome's install criteria](https://web.dev/articles/install-criteria). The service worker script is served from `/status/sw.js`, registers only in a secure context, and uses an exact allowlist for the generic, byte-identical `/status/` shell, `/assets/status.js`, the manifest, and those two static icons. It does not intercept `/api/*`, control routes, or unrelated pages. The private timezone and identity are fetched only after the shell loads and are never stored in Cache API. A cached shell can open after an auth session expires, but a fresh authenticated config read is required before any status data appears. Local bearer-header mode still cannot authenticate ordinary browser navigation; the intended browser deployment uses the existing Cloudflare Access flow.

The browser may download a replacement worker automatically, but it remains waiting until the user chooses **Apply app update**. **Check for app update** performs an explicit check. The worker activation removes only older caches under its own `workbench-status-shell-` prefix. Bump its cache version whenever the shell, script, or manifest changes so clients do not keep stale assets. Browser site-data controls remove the worker and shell cache. No service worker has been registered on a production origin by this source change, and no deployment or permission change is included.

Performance target for this slice: one dedicated script, no dashboard HTMX, preview stream or report data, one config request plus at most four selected widget requests per foreground check, and zero idle network requests. The precached shell, script, manifest and two resized icons total about 116 KB uncompressed; ordinary page rendering does not reference the icons. Each widget endpoint caps returned rows at 100 except attention's canonical derivation, which reads full action/run sets before capping output. Measure phone/desktop bytes and memory against the heavy dashboard before claiming a completed lightweight release. Synthetic tests and a disposable loopback browser preview establish manifest/scope/worker behavior, not live Cloudflare, target OS installation, or notification delivery.
