# Quick status first slice

`/status` is a small foreground view over canonical Workbench data. It uses existing operator authentication and requests `/api/status/{attention,jobs,hosts,allowances}` only for checked widgets. The browser stores widget names per profile in local storage, not account, job or notification payloads. Checkbox changes cancel prior requests and ignore late responses. Network refresh is explicit. In-memory countdowns and freshness labels update every 30 seconds while visible and immediately on resume; they never create a fresh observation. Offline state never presents cached data as live.

The allowance read model stores narrow manual observations in protected server SQLite. `POST /api/allowances/manual` accepts provider, product, local profile, bucket, window, timezone-aware `observed_at`, optional timezone-aware `reset_at`, and optional finite `remaining_percent`. No provider credentials or full exports are accepted. Observations are immutable for their exact key and time; an older import cannot replace a newer one. The latest per provider/product/profile/bucket/window is shown. Missing fields stay unknown and unusual reported percentages are preserved. The UI uses the configured reporting timezone and recomputes reset countdowns at render. Passing a reset marks refresh due, not a replenished balance. Entries older than one hour are stale; newer entries remain labeled manual, never verified live.

This slice has no automatic Codex, Claude or Gemini quota adapter. Supported interfaces must pass the evidence gate in [provider capabilities](provider-capabilities.md) before supplying data. No quota is inferred from message counts, context use or billing. The manual endpoint is accessible through authenticated generic `wb-api` requests; it is not a new MCP tool. Stale job records retain their reported state. No collector record means host visibility unknown.

The route uses existing operator authority. It does not issue a scoped companion credential, install a service worker, request notification permission, deliver push, subscribe to RGB, or cache private payloads offline. These remain gates for the fuller PWA in issue #187. No hardware driver is required. Reset choices restores the four default widgets; browser site-data controls clear the selection.

Performance target for this slice: one dedicated script, no dashboard HTMX, preview stream or report data, at most four foreground requests, and zero idle requests. Each endpoint caps rows at 100 except attention, whose canonical derivation reads full action/run sets. Measure phone/desktop bytes and memory against the heavy dashboard before claiming a completed lightweight PWA. Tests use synthetic records and do not establish live account or browser notification delivery.
